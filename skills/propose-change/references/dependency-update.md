# 依存や環境の更新

ライブラリやランタイムのバージョンを上げる変更で、変更の記録に書くことである。

| 項目 | 書くこと |
|---|---|
| 最初に示す証拠 | リリースノートと互換性の無い変更を読んだ結果と、更新の前にテストを動かした結果を示す。 |
| 確かめ方 | 互換性の無い変更のうち、導入先のコードが使っている所と、その確かめ方を書く。 |
| 作業の手順の最初 | 今のバージョンから上げる先までのリリースノートを読み、更新の前のテストの結果を残す。公開元と変更の中身は、セキュリティの確認（`audit-security`）で確かめ、結果を「調べたこと」に書く。 |

依存の追加は、人に確認を求める場面である（常に読むルールの節「人に確認を求める場面」）。
