# 複数の作業の並行

| 項目 | 内容 |
|---|---|
| 確かめたコミット | `b7d78e4` |
| 関わる変更の記録 | なし |

1つの依頼に独立した作業が複数あるときは、worktree（1つのリポジトリから作る、別の作業フォルダー）ごとに、実装役（worktreeで1つの作業を実装するサブエージェント）が並行で進める。並行で始めるかは、人が計画を見て決める。この文書には、始めるまでの流れ、実装役への渡し方、止まった実装役の再開のしかたを書く。

## 背景

独立した作業を1つずつ順に進めると、人がPRの下書きを待つ時間が、作業の数だけ増える。一方で、触るファイルが重なる作業を並行で進めると、競合と意味のずれが起き、成果物の質が下がる（[`architecture.md`の節「作業の要件」](../architecture.md#作業の要件)）。

## 要求

並行の流れは、`architecture.md`の名前付きの要件「複数の作業の並行」と「worktreeでの動作」（[節「作業の要件」](../architecture.md#作業の要件)）を満たす。

## 業務のルール

並行の作業は、次の順に進む。

1. 本体の会話が、計画で独立した作業を見つけ、並行で進めることを提案する。人が「並行で」と書かなくても提案する。
2. 本体の会話が、作業ごとに変更の記録を作り、人がまとめて承認する。
3. 実装役が、worktreeごとに、実装、テスト、レビュー、PRの下書きまで行う。
4. 本体の会話が、PRの下書きをまとめて人に示す。
5. 先のPRがマージされたら、本体の会話が残りのブランチに取り込み、テストを動かし直す。

| ルール | 理由 |
|---|---|
| 人が承認するまで、並行で始めない。 | 作業が独立しているかを、人が計画で確かめる。 |
| 計画では、触るファイルの重なり、順番に意味があるか、worktreeの外で共有するもの（例：DB、ポート番号、`.env`、Dockerのコンテナー）を確かめる。重なれば、順に進めることを提案する。 | worktreeが分けるのは作業フォルダーだけで、ほかのものは作業の間で共有される。 |
| 本体の会話は、実装役の依頼文に、ハーネスの場所、メインの作業フォルダー、変更の記録のパス、ブランチ名を入れる。 | worktreeのブランチ名は自動で付くので、実装役はブランチ名から変更の記録を探せない。 |
| マージのあとに残りのブランチに取り込んだら、テストを動かし直す。 | テキストの競合が出なくても、意味がずれることがある。 |
| 人の判断が要る場面では、実装役は問いを報告に書いて止まる。本体の会話が答えを送ると、実装役は文脈を保って再開する。 | サブエージェントは、人に問いを出すツール（`AskUserQuestion`）を使えない（この文書の節「前提」）。 |
| 再開した実装役は、作業フォルダーが最初に動いていたworktreeと同じ場所かを確かめ、違えば変更せずに止まる。 | 変更の前に止まった実装役は、再開すると本体の会話の作業フォルダーで動く（この文書の節「前提」）。 |
| 再開したときの確かめは、「worktreeの中か」ではなく、最初のworktreeと同じ場所かで行う。 | 本体の会話もworktreeで動く環境では、「worktreeの中か」は本体の会話のworktreeでも通ってしまう。 |
| 場所が違って止まったら、本体の会話が問いと答えを依頼文に足し、新しい実装役を起動する。 | 同じ実装役に答えを送り直しても、本体の会話の作業フォルダーで動く。 |

実装役が変更の記録をどこで直すかは、[`harness-folder.md`の節「メインの作業フォルダーの`.harness/`を読む」](harness-folder.md#メインの作業フォルダーのharnessを読む)に書く。

## 前提

| 前提 | 理由 |
|---|---|
| サブエージェントは、`AskUserQuestion`を使えない。 | サブエージェントの定義の`tools`の項目に書いても、最初の絞り込みで外れる（Create custom subagents）。 |
| worktreeで動くサブエージェント（`isolation: worktree`）が変更の前に止まると、worktreeが消え、再開したサブエージェントは本体の会話の作業フォルダーで動く。 | 変更しなかったworktreeは、自動で消える（Create custom subagents）。 |

## 判断

| 判断 | 誰が決めたか | 理由 |
|---|---|---|
| 計画は本体の会話で行う。人が計画を承認したあと、独立した作業を並行で進めるときだけ、worktreeごとに実装役が実装、テスト、レビュー、PRの下書きまで行う。 | [判断の記録](../../../docs/decisions/0006-subagent-count.md) | 並行でないときは、実装も本体の会話で行い、サブエージェントを増やさない。 |
