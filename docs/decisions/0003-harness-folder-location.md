# `.harness/`を導入先の中に置き、ハーネスのリポジトリにも同じ方法で入れてコミットする

| 項目 | 内容 |

| 状態 | 採った |

| 語の意味 | [`.harness/docs/ubiquitous-language.md`](../../.harness/docs/ubiquitous-language.md) |

## 背景

導入先ごとのルール、設定、文書を、導入先のgitに入れずに置く場所が要る。ハーネスのリポジトリでも、ハーネスを使って作業し、手元で直したルールが次のセッションからそのまま読み込まれる必要がある。

## 判断

- 導入先の中の`.harness/`に置き、`.git/info/exclude`でgitから外す。
- ハーネスのリポジトリにも、ほかの導入先と同じ方法（プラグインを有効にし、`configure-repository`で設定を書く）でハーネスを入れ、手元のファイルをそのまま読み込む。
- ハーネスのリポジトリでは、`.harness/`もコミットする。

## 案

### 置き場所

| 案 | 結果 | 理由 |
|---|---|---|
| 導入先の中の`.harness/`に置き、`.git/info/exclude`でgitから外す | 採った | 文書が導入先のそばにあり、チームに広げるときもファイルを移さずに済む。 |
| 導入先の外の個人用のフォルダー（`~/.config/my.harness/`）に置く | 採らなかった | サンドボックスがもともと書けない場所で、書き込み禁止を足さずに済むが、文書が導入先から離れ、チームに広げるときにファイルを移す必要がある。 |

### ハーネスのリポジトリへの入れ方

| 案 | 結果 | 理由 |
|---|---|---|
| ほかの導入先と同じ方法で入れ、手元のファイルをそのまま読み込む | 採った | 導入の方法が1つで済み、編集が次のセッションから読み込まれる。 |
| ハーネスのリポジトリ用に、別の導入の方法かコピーを作る | 採らなかった | 編集のたびに入れ直す作業が要り、元とコピーが食い違う。 |

### ハーネスのリポジトリの`.harness/`

| 案 | 結果 | 理由 |
|---|---|---|
| `.harness/`もコミットする | 採った | ほかの導入先で外すのはチームの合意が要るためで、作者のリポジトリには当てはまらない。コミットすれば、どのPCでも同じルールと設定になり、変更をPRとレビューで確かめられる。 |
| ほかの導入先と同じく、`.git/info/exclude`で外す | 採らなかった | PCごとにルールと設定を書き直すことになり、変更の履歴も残らない。 |

## 結果と失うもの

`.harness/`は作業フォルダーの中なので、ルールと設定を保護するために、サンドボックスの書き込み禁止と、Edit、Writeへの権限の確認を足す。
