# 導入先のコミットメッセージの本文の形を、導入のときに人が決める

| 項目 | 内容 |
|---|---|
| 状態 | 採った |
| 決めた日 | 2026-11-14 |
| 関わる設計 | [`.harness/docs/architecture.md`の節「導入」](../../.harness/docs/architecture.md#導入) |
| 語の意味 | [`.harness/docs/ubiquitous-language.md`](../../.harness/docs/ubiquitous-language.md) |

## 背景

ハーネスの既定では、コミットメッセージの本文を「背景：」「要求：」「方法：」の段落で書き、変更の理由を残す（`rules/git.md`の節「コミットメッセージ」）。導入先では、書き方は導入先の形を先にする（`rules/always-read.md`の節「導入先で書き方を決める順」）。最初の行の形によく使われるConventional Commits 1.0.0では、本文は任意である。そのため、導入先の履歴が本文の無いコミットだけでも、チームが本文を書かないと決めたのか、決めていないだけなのかは、履歴からは見分けられない。

## 判断

最初の行は、導入先の形に従う。本文の形が導入先のルールで決まっていなければ、`configure-repository`が、背景、要求、方法の中身を導入先の言語で書く案を示し、人が決めた形を、エージェントが導入先ごとのルールに書く。

## 案

| 案 | 結果 | 理由 |
|---|---|---|
| 最初の行は導入先の形にし、本文の形は導入のときに人が決めて、導入先ごとのルールに書く | 採った | 導入先の形を先にしたまま、変更の理由をコミットに残せる。導入のときの1回で決まり、コミットのたびに迷わない。 |
| 導入先でも、日本語の「背景：」「要求：」「方法：」の見出しで書く | 採らなかった | 英語の履歴に日本語の見出しが混ざり、導入先の形と食い違う。 |
| 直近の履歴に合わせ、本文が無ければ書かない | 採らなかった | 変更の理由がコミットに残らない。背景のとおり、本文の無い履歴は、チームが書かないと決めたことを示さない。 |
| コミットのたびに人に聞く | 採らなかった | 同じ問いが毎回出て、人の手間が増える。 |

## 結果と失うもの

導入のときに、人が決める項目が1つ増える。決めた形は導入先ごとのルールに書くので、`SessionStart`のフックが渡す字数をその分使う。

## 見直す条件

導入先で、決めた形で書いた本文が、チームのレビューで直されることが続いたときに見直す。
