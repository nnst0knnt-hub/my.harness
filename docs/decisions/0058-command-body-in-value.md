# `gh`と`glab`の本文は、値に書く形だけを通す

| 項目 | 内容 |
|---|---|
| 状態 | 採った |
| 決めた日 | 2026-11-19 |

| 語の意味 | [`.harness/docs/ubiquitous-language.md`](../../.harness/docs/ubiquitous-language.md) |

## 背景

外で動く`gh`と`glab`は、本文をファイルから読む形（例：`--body-file`、`-F body=@<ファイル>`）で、シンボリックリンクの先にある、サンドボックスが読めなくしたファイル（例：`~/.ssh/id_ed25519`）も読んで送れる。人が確認で見るのはファイルのパスだけで、ファイルの中身は判定のあとにも書き換えられる。

## 判断

書き込みの`gh`と`glab`では、本文を値に書く形だけを通し、ファイル、エディター、標準入力から読む形を止める。止める形と送り方は、関わる設計の2つに書く。

## 案

| 案 | 結果 | 理由 |
|---|---|---|
| 値に書く形だけを通す | 採った | 判定のスクリプトと人が、送る本文そのものを見られる。 |
| ファイルから読む形も、確認を求めて通す | 採らなかった | 確認で人が見るのはパスだけで、リンクの先の秘密鍵や、判定のあとに書き換えた中身が送られる。 |
| 判定のときに、ファイルの中身を書き込めない場所へコピーして送る | 採らなかった | コピーと送り方の新しい仕組みと、そのテストが要る。 |

## 結果と失うもの

本文の`'`を`'"'"'`と書くような、値に書く形の規則が増え、長い本文もコマンドの文字列に入る。

## 見直す条件

外の`gh`と`glab`が読むファイルの中身を、確認の画面に出せるようになったときに見直す。
