# PRの範囲の外の`MUST`は、PRを作る前の確認で、直すか分けるかを人が決める

## 背景

3回目のレビューで残る`MUST`が、PRの範囲の外の問題（例：設計の前提）のことがある。範囲の外の問題をPRの中で直し続けると、PRの範囲が広がり、レビューが終わらない。

## 判断

3回目で残ったPRの範囲の外の`MUST`は、作業を止めずにチケットに分ける案にし、直すか分けるかを、PRを作る前の確認で人が決める。中身は、冒頭の表の「関わる設計」に書く。

## 案

| 案 | 結果 | 理由 |
|---|---|---|
| エージェントがPRを作る前の確認のときに人に示し、セキュリティの`MUST`を先頭に並べる | 採った | PRとチケットの作成は、もともと人に確認を求める場面で、確認の回数が増えない。セキュリティを先頭にするのは、一度起きると取り消せない問題（例：秘密情報の漏れ）があるためである。 |
| 分ける案にしたときに、作業を止めて人に聞く | 採らなかった | 作業が止まり、人の手間が増える。 |
| セキュリティの`MUST`は分けず、必ずこのPRで直す | 採らなかった | 設計の前提のような大きな問題があると、PRが終わらない。 |
| 範囲の外の`MUST`も、すべてこのPRで直す | 採らなかった | PRの範囲が広がり、レビューが終わらない。 |

## 結果と失うもの

- 人が分けると決めた`MUST`は、マージのあとも残る。PRの本文の節「残っていること」（残したことと理由を書く節）と、チケットで追う。
- 範囲の外かどうかは、エージェントが判断する。人は、PRを作る前の確認のときにその判断を見直せる。
- 分ける案にした`MUST`は、レビューを終える条件に数えない。数えると、直しの差分が無いまま5回目で止まる。
