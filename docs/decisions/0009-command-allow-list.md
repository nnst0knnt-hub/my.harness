# コマンドは簡単な形だけを通し、判定のスクリプトは文字列を受け取り、JSONは`jq`で読む

## 背景

- `git push`と`gh`のコマンドは、書き方が多い（例：区切りの記号、オプションの順）。文字列を細かく解析して止める処理は、回避方法が見つかるたびに大きくなる。
- 判定のスクリプトを呼ぶ側（例：Claude Codeのフック、テスト、ほかのエージェントのフック）ごとに、渡す情報の形が違う。
- Claude Codeは、動かすコマンドのような情報をJSONでフックに渡す。`jq`が無いPCもある。

## 判断

- 判定できる簡単な形だけを通し、判定できない形は止め、理由の文で簡単な形を示す（許す一覧）。
- 判定のスクリプトは、コマンドの文字列を引数で受け取る。Claude CodeのJSONは、`hooks/`の処理が読んで渡す。
- Claude Code用の処理だけで`jq`を使い、無ければ人に確認を求める。

## 案

### 判定の範囲

| 案 | 結果 | 理由 |
|---|---|---|
| 判定できない形は止める | 採った | 確認が出ず、エージェントが書き直す。誤って通ったpushは、足した`pre-push`（動かすgitが2.54以上）と、使えればブランチ保護が止める。 |
| 判定できない形は確認を求める | 採らなかった | 確認が出続け、外で動くつないだ形を人が認めると、保護するブランチに届きうる。 |
| 文字列を細かく解析し、すべての書き方を見分ける | 採らなかった | 処理が大きくなり続ける。 |

### 判定のスクリプトの入力

| 案 | 結果 | 理由 |
|---|---|---|
| コマンドの文字列を引数で受け取る | 採った | 形を変える処理を呼ぶ側に置けば、エージェントごとの知識が共通の部分に入らない。 |
| 呼ぶ側のJSONを、判定のスクリプトが読む | 採らなかった | エージェントごとの知識が共通の部分に入る。 |

### JSONの読み方

| 案 | 結果 | 理由 |
|---|---|---|
| Claude Code用の処理だけで`jq`を使い、無ければ確認を求める | 採った | `jq`はJSONを正しく読め、無くても作業を続けられる。公式の文書の例も`jq`を使う。 |
| bashだけでJSONを読む | 採らなかった | エスケープ（例：`\"`、`\u`）を読み誤りやすく、誤ると通してはいけないものを通す。 |
| `jq`を必須にする | 採らなかった | `jq`が無いPCで何もできない。 |

## 結果と失うもの

簡単な形でなければ、作業用のブランチへでも止まる。Claude Codeが区切れないコマンドは、外に出す形でなくても止まる。判定のスクリプトは`jq`が無くても動き、テストは文字列を渡すだけで書ける。
