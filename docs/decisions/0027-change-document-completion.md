# gitで追跡する変更の記録は、PRの最後のコミットで「完了」にする

| 語の意味 | [`.harness/docs/ubiquitous-language.md`](../../.harness/docs/ubiquitous-language.md) |

## 背景

変更の記録は、PRの作業が終わったら状態を「完了」にし、マージされて「完了」になったあとは書き換えない。導入先の`.harness/`はgitの外にあるので、エージェントは、マージを知ったとき（人に伝えられたか、`gh pr view`で見たとき）に変更の記録を「完了」に書き換えられる。ハーネスのリポジトリでは`.harness/`もコミットするので、マージのあとに変更の記録を書き換えるには、新しいコミットとPRが要る。

## 判断

gitで追跡する変更の記録は、PRを作る前の確認のあとに状態を「完了」にしてコミットし、PRに入れる。マージのあとは書き換えない。gitで追跡しない変更の記録は、エージェントがマージを知ったときに「完了」にする。

## 案

| 案 | 結果 | 理由 |
|---|---|---|
| PRの最後のコミットで「完了」にする | 採った | 変更の記録を書き換えるためだけのPRが要らない。`main`に入る変更の記録は、マージされたPRのものだけになる。 |
| マージのあとに、書き換えのPRで「完了」にする | 採らなかった | 変更の記録のためだけのPRがPRごとに1つ増え、そのたびにCIと人の承認が要る。 |

## 結果と失うもの

マージの前に「完了」と書くので、PRを作ったあとに直したときは、変更の記録の節「確かめ方」と「残っていること」も、その直しと同じコミットで直す。マージされずに閉じたPRの変更の記録は、`main`に入らない。

## 見直す条件

ハーネスのリポジトリで、作者のほかにもPRを作る人が増え、マージの前の「完了」をマージ済みと読み違える場面が出たときに見直す。
