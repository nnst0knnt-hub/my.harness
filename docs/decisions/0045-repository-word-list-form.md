# 導入先ごとの語の一覧は`.harness/rules/`に置き、確かめる語をパターンで指す

| 項目 | 内容 |
|---|---|
| 状態 | 採った |
| 決めた日 | 2026-11-19 |
| 関わる設計 | [`features/harness-folder.md`の節「導入先ごとの語の一覧」](../../.harness/docs/features/harness-folder.md#導入先ごとの語の一覧) |
| 語の意味 | [`.harness/docs/ubiquitous-language.md`](../../.harness/docs/ubiquitous-language.md) |

## 背景

導入先では、確かめる語への人の答えと、その導入先だけで止める語を、次のセッションも読める場所に残す必要がある。

## 判断

導入先ごとの語の一覧を、メインの作業フォルダーの`.harness/rules/word-list.txt`に置き、確かめる語への答えはパターンの文字列で指す。どの導入先でも使わない語も、導入先で指摘したら一覧に足す。

## 案

### 置き場所

| 案 | 結果 | 理由 |
|---|---|---|
| `.harness/rules/word-list.txt` | 採った | 書き込み禁止と確認がフォルダーで当たり、保護の設定を足さずに済む。フックは`always-read.md`だけを渡すので、文脈を使わない。 |
| `.harness/config`（git configの形）に書く | 採らなかった | 値の中の`\`、`"`、`#`、`;`にエスケープが要り、パターンが崩れる。 |
| `.harness/`の直下に置く | 採らなかった | 書き込み禁止と確認を導入先とPCの設定に足す必要があり、足し忘れると人の確認なしに書ける。 |

### 形

| 案 | 結果 | 理由 |
|---|---|---|
| 1ファイルで1列目を種類にし、答えはパターンの文字列で指す | 採った | 代わりの言い方と除く形を毎回ハーネスの一覧から読むので、ハーネスの直しが導入先に届く。逆の答えを、1つのファイルの中で見つけられる。 |
| 確かめる語の行を、導入先へ行ごとコピーする | 採らなかった | ハーネスが除く形を直しても導入先に届かず、誤検知が残る。 |
| 禁止にする語と禁止にしない語で、ファイルを分ける | 採らなかった | 逆の答えが2つのファイルにまたがり、読む処理が増える。 |

### 導入先で指摘した語

| 案 | 結果 | 理由 |
|---|---|---|
| どの導入先でもの語も、Issueと一覧の両方に足す | 採った | ハーネスのPRを待たずに、次の確認からその導入先で止まる。 |
| どの導入先でもの語は、Issueだけにする | 採らなかった | ハーネスのPRがマージされるまで、その導入先でも止まらない。 |

## 結果と失うもの

ハーネスが確かめる語のパターンを変えると、導入先の答えが外れ、その語を聞き直す。外れた答えの行は、導入先で消すまで、語の確認のたびに知らせが出る。一覧はgitから外すので、ほかのPCとcloneのし直しでは無くなる。

## 見直す条件

導入先のチームが`.harness/`をコミットし、一覧を共有すると決めたら見直す。
