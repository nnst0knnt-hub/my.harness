# 常に読むルールには、判断の基準と短い指示だけを入れる

## 背景

書き方のルールは、`rules/writing.md`の1つだけでも`SessionStart`のフックが渡せる上限の10,000字を超え、常に読むルールの字数の目安にも入らない。

## 判断

常に読むルールには、判断の基準と短い指示だけを入れる。書き方の本文（例：`rules/writing.md`、`rules/git.md`）は、常に読むルールが、文章やコミットを書く前にエージェントに開いて読ませる。

## 案

| 案 | 結果 | 理由 |
|---|---|---|
| 判断の基準と短い指示だけを入れ、書き方の本文は書く前に読む | 採った | 字数の目安と上限に入り、書く場面ごとに要る部分だけを読める。 |
| 書き方の本文も、常に読むルールに入れる | 採らなかった | 字数の目安と上限に入らない。 |

## 結果と失うもの

エージェントが「書く前に読む」の1行に従うことに頼る。従う割合を示した公式の数字は、見つかっていない。書き方のルールから外れた所は、次の3つで防ぐか見つける。

- 機械で確かめられる語と表記は、`scripts/`の文章の確認のスクリプトが、動かすたびに見つける。
- コミットやPRを書くスキルの手順に、`rules/git.md`を読む手順を書く。
- 機械で確かめられない文の長さや段落は、書く人が確かめる。読み手が事実を誤って読む所だけを、別の文脈のレビュー役が、マージを止める指摘（`MUST`）で挙げる。

## 見直す条件

書き方の外れについての「人の指摘」のラベルのIssueが続けば、書き方の要点も常に読むルールに入れる。続いたかは、人がIssueの一覧を見て決める。共通のルールが字数の目安を超えたら、入れる範囲を見直す。
